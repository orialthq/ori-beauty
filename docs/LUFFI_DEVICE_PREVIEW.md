# luffi 휴대폰 미리보기

작업 브랜치: `feature/luffi-batch-device-preview`

기준: `dev`의 `3e6bf83`
병합 조건: 사용자가 실제 휴대폰의 디자인을 확인하고 승인한 뒤 `dev`에 병합한다. `main`에는 반영하지 않는다.

## 이번 변경

- 앱 표시 이름을 **luffi (러피)**로 변경했다. 돛과 미소 같은 물결을 조합한 오리지널 심볼, 차분한 민트 색상을 홈·메뉴·공유 카드·앱 아이콘·시작 화면에 적용했다.
- 기존 설치를 업데이트할 수 있도록 Android/iOS 식별자, 저장 데이터, 네이티브 채널, `.trunon` 공유 파일 형식은 유지했다.
- 사진 선택 한도는 한 번에 **100장 / 전체 512MiB**, 개별 분석 이미지는 **12MiB**다. 100장은 한 사진에 합치는 것이 아니라 독립된 콘텐츠 100개다.
- **절약해서 정리**가 기본이다. 사진을 서버에 접수한 뒤 실제 OpenAI Batch API로 분석한다. 같은 이미지 분석의 일반 API 요금 대비 50% 할인 대상이며, 접수 후 최대 24시간의 비동기 처리다. 장소 검색 등 별도 API 비용까지 50% 할인되는 것은 아니다.
- **바로 정리**는 일반 동기 API를 사용하며 최대 **10장 동시 처리**한다. 동시 처리 자체가 할인은 아니다. 기존 3장 제한은 모바일 메모리와 요청량을 제한하기 위한 초기 설정이었다.

## 휴대폰에서 확인할 순서

1. 앱 아이콘과 앱 이름, 시작 화면, 홈의 새 심볼·문구를 확인한다.
2. 메뉴에서 콘텐츠 → 추가를 열고 두 분석 모드를 확인한다.
3. 절약 모드에서 우선 2~3장을 선택한다. 콘텐츠 목록의 접수 대기 → 접수 완료 → 분석 대기 표시를 확인한다.
4. 접수 완료 뒤 앱을 종료했다가 다시 열고 결과 새로고침을 누른다. 접수된 작업은 기존 요청 ID로 이어받아야 한다.
5. 완료된 콘텐츠를 열어 원본 사진과 분석 결과가 맞게 연결되는지 확인하고 정리함·계획함으로 이어서 사용한다.
6. 대량 테스트는 10장, 이후 75장으로 늘린다. 바로 정리 모드와 절약 모드를 혼동하지 않도록 확인한다.
7. 공유 미리보기·받은 팁·백업/삭제 안내에서도 luffi 이름이 통일되어 있는지 확인한다.

## 개발 서버 운용과 비용 안전장치

- 휴대폰의 접수 대기 사진을 올리고 결과를 동기화하려면 Mac의 로컬 분석 서버가 실행 중이어야 한다. 무선 연결 후 `adb reverse tcp:8787 tcp:8787`을 다시 설정한다.
- OpenAI가 접수한 배치는 휴대폰 앱이나 Mac이 잠들어도 제공자 측에서 처리된다. Mac 서버와 휴대폰이 다시 연결되면 결과를 동기화한다.
- 서버 접수 전 요청 ID를 휴대폰 저장소에 기록한다. 서버도 작업과 배치 생성 상태를 디스크에 저장한다.
- 동일 ID 재전송은 같은 작업으로 취급한다. 배치 생성 응답이 유실되면 제공자 메타데이터로 확인하고, 확인 전 새 유료 작업을 만들지 않는다.
- 실패·만료의 명시적 재시도는 새 요청이다. 이미 과금된 부분이 있을 수 있다. 앱에서 항목을 지우는 것은 이미 제공자에 접수된 작업의 취소를 의미하지 않는다.
- 서버의 개인 작업 파일은 `server/.local/batch-jobs`에 저장되며 Git에서 제외된다. 이 폴더를 지우거나 다른 서버 저장소로 바꾸면 기존 접수 내역을 찾을 수 없으므로 진행 중에는 보존해야 한다.
- 서버 결과 보관 기간과 정리 정책은 [서버 설명](../server/README.md)을 참고한다. 장기간 앱을 열지 않기 전에 결과 동기화를 마치는 편이 안전하다.

공식 동작 기준: [OpenAI Batch 가이드](https://developers.openai.com/api/docs/guides/batch).

## 검증 구분

자동 테스트는 가짜 API 응답으로 75장 큐, 요청 ID의 저장·중복 방지, 재시작, 결과 순서 변경, 만료, 삭제 경합을 검증한다. 이것은 실제 75장 유료 분석 완료를 의미하지 않는다. 실제 제공자 접수와 휴대폰 설치·디자인 승인은 별도로 확인한다.

### 2026-09-06 검증 기록

- Flutter 전체 테스트 363개 통과, 최종 안내 문구/선택기 변경 후 관련 화면 테스트 24개 추가 실행 통과
- Node 서버 전체 테스트 198개 통과
- Flutter 정적 검사 통과, Android debug APK 빌드 성공
- 실제 luffi 로고 1장으로 유료 Batch 요청 접수와 결과 수신(`completed`)까지 확인했다. 로고에 실행 가능한 콘텐츠가 없으므로 `unsupported` 결과를 정상 수신·검증·저장했다. 실제 사진 75장의 품질·비용 평가는 별도다.
- 홈/분석 선택 화면을 앱 코드로 렌더링하고 시각 확인했다. `artifacts/luffi-preview`의 미리보기는 실기기 캡처가 아니다.
- 새 휴대폰 주소 `192.168.219.46:44583`로 연결했다. 디버깅 프로그램 재시작 후 Samsung SM-S916N에 기존 데이터를 유지하는 업데이트 설치가 성공했고, luffi 홈 화면 실행과 새 문구 표시를 확인했다. 분석 서버 8787 포트 연결도 설정했다. 이후 사용자가 다른 앱으로 전환하여 추가 화면 조작을 중단했으며, 디자인 승인은 아직 대기 중이다.
- `dev`는 `3e6bf83`, `main`은 `09db1807` 그대로이며 이번 변경은 병합하지 않았다.
