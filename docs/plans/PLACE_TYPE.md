# 장소형

가서 하는 것. 맛집·카페, 장소, 뷰티숍. 계획의 세 성격 중 먼저 만드는
것이고, 유일하게 근처 알림이 성립한다.

[계획 전체](README.md) · [추천](RECOMMENDATION.md)

## 위치는 이미 있다 — 다만 글자로

저장된 대상은 위치를 갖고 있다. 이름, 주소(`서울 중구 을지로14길 21`),
`searchArea`(`성수`, `을지로` 같은 사람이 쓰는 지역어). 사람이 읽고 지도앱이
찾기에 충분하다.

실제로 지도·길찾기·공유가 지금 다 된다. 좌표를 쓰지 않기 때문이다. 검색어를
URL에 붙여 넘길 뿐이다.

```
https://map.naver.com/p/search/화육계 을지로
```

[추천](RECOMMENDATION.md)도 마찬가지다. `성수`와 `성수`를 맞추는 데 숫자는 필요
없다.

**근처 알림만 다르다.** 지오펜스 등록 API는 이렇게 생겼다.

```swift
CLCircularRegion(center: 위도·경도, radius: 미터)
```

주소 문자열을 받는 자리가 없다. iOS도 Android도 같다. "이 가게 근처에 오면
알려줘"를 OS에 부탁하려면 숫자 두 개가 반드시 있어야 한다.

| 기능 | 필요한 것 | 지금 |
|---|---|---|
| 지도·길찾기·공유 | 검색어 | 된다 |
| 추천 | 지역 글자 | 된다 |
| **근처 알림** | **위경도** | 없다 |

좌표는 근처 알림 하나 때문에 필요하다. 나머지는 지금 상태로 굴러간다.

## 좌표를 어떻게 얻나

**공짜 지오코딩이 이미 앱에 들어 있다.** 계획 만들 때 사용자가 적은 장소를
좌표로 바꾸는 기능이 지금도 돌고 있다.

- iOS — 애플 `CLGeocoder` (`NativeTriggerSchedulerBridge.swift`)
- Android — 기본 `Geocoder`, 한국 로케일 (`TriggerLocationResolver.kt`)

키도 비용도 없다. 저장된 대상의 주소를 여기에 넣으면 된다.

### 먼저 재볼 것

만들기 전에 이것부터 잰다.

1. 저장된 캡처들의 **주소가 얼마나 제대로 뽑혔나** — 도로명 주소인가, SNS
   위치 태그(동네 이름)인가
2. 그 주소를 **OS 지오코더에 넣으면 몇 %나** 쓸 만한 좌표가 나오나

주소가 잘 나오면 이걸로 끝난다. 저장된 캡처 몇 개로 몇 분이면 잰다.

### 카카오는 보험이다

서버에 `/v1/resolve-place`와 카카오 연결이 이미 있다. 다만 앱이 부르지 않고,
`KAKAO_REST_API_KEY`도 없어 꺼져 있다.

카카오가 더 나은 지점은 두 가지뿐이다.

- **상호명 검색.** OS 지오코더는 주소에 강하고 상호명에 약하다. `화육계 을지로`
  같은 입력은 카카오가 낫다
- **장소 ID.** 같은 가게를 여러 번 캡처했을 때 하나로 묶는 판단. 볼트
  `ENT-001`의 1순위 규칙이다

둘 다 지금 당장 필요하지 않다. **위에서 잰 결과 좌표가 충분히 안 나올 때**
꺼내는 카드로 둔다. 전제 조건이 아니다.

## 근처 알림

네이티브는 이미 다 있다. iOS는 `CLCircularRegion`, Android는 지오펜스.
쿨다운·시간창·중복제거·스누즈까지 구현돼 있다.

없는 것은 **규칙**이다. 언제 알리고 언제는 안 알릴지가 정해져 있지 않다.

지금 코드에 박힌 기본값 — 쿨다운 6시간, 중복 판정 창 1분, 스누즈 30분, 시간창은
선택 — 이 맞는지 판단할 근거가 없다.

근처 알림은 잘못 울리면 그날로 꺼지는 기능이다. 출근길에 매일 울리면 끝이다.
붙이기 전에 최소한 이것들은 정해야 한다.

- **하루에 몇 번까지** 울릴 수 있나
- **이동 중**(차·지하철)인지 구분하나, 아니면 구분하지 않나
- **시간대를 제한**하나. 맛집이면 식사 시간, 뷰티숍이면 영업 시간
- 같은 곳을 **몇 번 무시하면** 그만 울리나

### 지오펜스 20개 상한

iOS가 한 앱에 동시 감시할 수 있는 리전은 20개다. Android는 100개.

저장한 장소가 21곳이 되는 순간 무엇을 등록하고 무엇을 버릴지 정해야 한다.
[추천](RECOMMENDATION.md) 판단을 여기에도 쓰면 "지금 가장 그럴듯한 20곳"을 고를 수
있다.

코드는 이미 상한을 넘으면 `geofence_limit_exceeded`로 명시적으로 알린다.
조용히 실패하지는 않는다.

### 권한

배경 위치("항상 허용")가 필수다. iOS에서 가장 받기 어려운 권한이고, "앱 사용
중에만"이면 리전 감시가 아예 걸리지 않는다.

재설치할 때마다 권한이 초기화된다는 것도 개발 중에 계속 부딪힌다.

이 권한을 실제로 몇 명이 주는지가 이 기능의 실체다. 볼트가 근처 알림에 매긴
`data_feasibility_score: 2`(= 만들기 보류 조건)의 근거가 바로 이것이고, 만들어본
지금은 실기기에서 다시 잴 수 있다.

## 시각 트리거의 판정 시점

Android는 알람이 울린 뒤 조건을 검사한다. iOS는 `UNCalendarNotificationTrigger`로
시스템에 미리 등록하는 구조라 예약 시점에 판정이 확정된다.

위치 트리거는 iOS도 `didEnterRegion`에서 조건을 제대로 검사한다. 시각 트리거만
다르다.

iOS가 백그라운드 실행을 주지 않으니 구조적으로 불가피하지만, 등록 후 조건이
바뀌면 어긋날 수 있다. 추천을 알림 직전에 다시 부르려면 iOS에서는 이 제약이
걸린다.
